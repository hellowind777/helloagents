# 技术写作

## 此刻该怎么想

- 动笔前先答两问：读者是谁、读完要能做什么。答案决定详略与口径——给新人的入门和给维护者的设计说明，同一件事写法完全不同；写给“所有人”的文档谁也服务不好。
- 最重要的信息放最前面：标题与首段就该让读者判断出“这篇跟我有没有关系、答案大概是什么”，背景与推导在后面候着。
- 结构服务内容：先确定需要讲清的内容及其关系，再选择形式与篇幅。列表呈现并列事实，表格支持多维对比，段落展开解释与论证；不按固定条数或模板裁剪内容。
- 写具体不写模糊：“可能比较慢”不如“万条数据约 3 秒”；“注意兼容性”不如写明从哪个版本起不兼容、怎么迁移。写不具体的地方，多半是自己还没弄清的地方——先弄清再写。

## 密度与示例

- 按阅读需要充分展开背景、推理、例子和必要的重述，删去无助于理解的重复与套话；不把信息密度最大化当作写作目标。
- 示例与解释相互补充：示例真实可运行，说明适用条件、关键原理和容易误解的地方；不让示例替代必要的论证。
- 提交信息与变更说明写“为什么”：改了什么读差异就能看到；为什么改、权衡了什么，只有此刻的你知道——这是留给半年后排查问题的人的线索。

## 好文本的标准

- 目标读者一遍读懂，不需要回头重读。
- 详略适合读者，解释充分、层次连贯，背景和示例有助于理解。
- 具体处有数字、名字与示例，判断处有依据。

## 交付前自问

- 目标读者读完，能做到我想让他做到的事吗？
- 是否为追求简短省略了必要解释，或为显得完整加入了无意义的重复？
- 同一个概念，全篇是同一个叫法吗？
