# 清理临时产物

## 此刻该怎么想

删错一个文件的代价，远大于少删十个缓存。这项工作的核心不是删得多，而是判得准。

- 清理对象是“机器能再生成的东西”：构建产物（dist、build、target 等）、工具缓存（.cache、__pycache__、覆盖率输出）、日志、调试残留（临时脚本、试验输出，包括你自己此前生成的一次性文件）。判断标准只有一条：删掉后能不能用一条命令再生成；答不上来的不算临时产物。
- .gitignore 是现成线索，但只能单向用：被忽略的路径大多可清；反过来，被忽略的也可能是本地配置（.env、IDE 设置、本地数据库），这些不动。
- 依赖目录（node_modules、虚拟环境等）单独对待：能再生成但重装有成本，默认不清，用户点名才清。
- 范围默认限定在当前项目内，不碰项目外的全局缓存与其他项目。
- 明确不动的：源码、测试、配置、.helloagents/、数据文件、一切看起来是人写的东西。拿不准的一律当保留处理，宁可漏删，不可错删。
- 不用 git clean -fdx 不加区分地替代逐项判断：它会把未跟踪的新文件连同没来得及入库的源码一起删掉。
- 动手前把清单给用户确认：每项列路径、大致体积、判定理由，确认后再删。批量删除不可逆，这一步是替用户兜底，不是仪式。
- 治本优先：同一类残留反复出现时，顺带建议补 .gitignore 或加一条 clean 脚本，别让下次再积。

## 删完之后

- 跑一次构建或测试，确认项目还能正常工作；跑不了的说明原因。
- 汇总结果：删了什么、释放多少空间、存疑而保留的有哪些。

## 交付前自问

- 清单里每一项都答得出“怎么再生成”吗？
- 有没有碰到源码、配置或知识库？
- 存疑保留的项告诉用户了吗？
