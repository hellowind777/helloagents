# 设计判断

## 此刻该怎么想

- 先形成设计意图再写代码：给谁用、解决什么问题、希望用户产生什么感受。这三问答不出来，选出的颜色和组件只是排版，不是设计。
- 先确定页面的核心任务、信息优先级、内容节奏和视觉气质，再选择布局、色彩、字体与组件；每项设计选择都应服务明确目标。
- 先提出并比较少量合理的视觉方向，再选择最符合产品定位和页面任务的一种；不为展示方案而堆砌无效选项。
- 根据产品定位确定清晰的视觉方向并保持一致；需要建立品牌记忆点时再强化独特表达，工具和信息密集型界面优先保证层级、效率与可读性。
- 缺少现成约束时警惕滑向默认审美；差异化要服务产品语义与可用性，不为不同而不同。
- 项目里有 .helloagents/DESIGN.md 或既有设计系统时先读再动手，延续并扩展已有视觉语言；没有时根据产品定位建立完整、统一且足以支撑当前界面及其后续扩展的设计基础。
- 用真实内容设计：真实文案、真实数据、真实长度。假文和整齐的假数据会掩盖布局问题，真实内容会逼出正确的设计决策。
- 复杂度匹配场景：营销页可以浓烈，工具页要克制。信息密集的界面，层级清晰就是最好的装饰。

## 设计基础

动手前定下这几件事，全部落成变量或主题配置，不散落在组件里：

- 色彩、排版、间距、形状和动效统一放入变量或主题配置；设计基础应服务整体视觉方向、信息层级和交互状态，不因追求最少规则而牺牲完成度。
- 组件和入口服务于用户任务、信息层级和视觉一致性；避免无明确作用的重复和堆砌。

## 状态与交互

- 每个异步界面覆盖加载、空、错误、成功四态，外加禁用态。空状态告诉用户能做什么；错误状态说清原因与下一步，不接受一句“出错了”。
- 加载优先用骨架占位而不是转圈；内容出现时不引起布局跳动。
- 焦点不能丢：弹窗打开时困住焦点、关闭后归位；提交出错后焦点落到第一个错误字段。
- 表单：标签可见、错误信息紧挨字段、提交中按钮禁用并有进行中反馈。
- 破坏性操作用语义危险色，并与常规操作在位置上分开。

## 可访问性与适配

与视觉同步达标，不是收尾补丁：

- 遵循目标平台的对比度和可访问性规范；不单靠颜色传达信息，辅以图标或文字。
- 用语义化结构表达页面：标题层级、地标区域、控件角色正确，辅助技术才有东西可读。
- 交互元素全部可键盘操作、焦点可见；尊重系统的减弱动效设置。
- 按产品主场景确定首要视口，再适配其余；尺寸以可读性和目标平台规范为准。

## 需要避免的倾向

在本次任务涉及的界面范围内，避免以下问题；无关页面的问题不要顺手扩大处理范围：

- 无依据地使用默认渐变、渐变大标题或其他流行样式；只有它们服务于产品定位和信息层级时才使用。
- 卡片堆砌：去掉边框、阴影、圆角后不影响理解的，就不该是卡片。
- emoji 当图标、默认字体栈、千篇一律的三栏特性布局。
- 首屏堆满徽章、标签、统计数字互相抢戏；每个区块只做一件事。
- 万物居中、处处等宽的均匀布局——没有层级的页面读不出重点。
- 品牌缺席：遮住产品名后首屏可以属于任何产品，说明设计还没开始。

## 好界面的标准

- 有品牌表达目标时，建立可辨识的设计特征；既有后台、表单和信息密集界面以任务效率、一致性和可读性为完成标准，不强加视觉记忆点。
- 变量一改全站生效，没有漏网的硬编码色值与字号。
- 关键状态齐全，键盘走得通，目标视口都不破版。

## 交付前自问

- 界面是否实现了目标用户的核心任务？有品牌表达目标时，再检查其视觉特征是否清晰可辨。
- 加载、空、错误三态真的做了吗，还是只做了成功路径？
- 页面层级清楚，视觉重点明确，内容密度与产品场景匹配，组件状态和间距保持一致，整体结果体现出明确的产品特征吗？
- 实现后通过截图、浏览器预览或实际运行结果检查主要视口和关键状态，重点观察层级、间距、对齐、密度、溢出和视觉焦点；发现问题就迭代，直到结果符合设计意图。
