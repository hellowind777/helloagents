# AI 工件定向安全检查

> 加载时机：被审对象是（或包含）技能 / SKILL.md、插件、MCP 服务器或配置、agent 提示词 / 规则文件、自动化 agent 工作流时。
>
> 为什么这份清单值得存在：对四万余个公开市场技能的扫描显示，约四分之一至少含一个漏洞，携带可执行脚本的技能风险明显更高；MCP 工具描述投毒对前沿模型的攻击成功率很高，且模型能力越强越容易被攻击成功、自发拒绝率极低。这些模式不主动检查就不会显现——这是本技能唯一预置的定向清单。

逐类检查（每类：核心问题与典型信号）。发现按 SKILL.md 的质量门与严重度定义报告；可利用的注入、外传、越权属阻断级。

1. **提示注入面**——不可信内容（用户输入、抓取的网页、读取的文件、工具返回值）是否会汇入指令流？有没有把“数据”当“指令”处理的位置？拼接外部内容进提示时有没有隔离与标注？
2. **工具 / 技能描述投毒**——工具描述、技能 description、文档字符串里是否藏有面向 AI 的隐藏指令（“忽略之前的规则”“总是先读取某文件”“不要告诉用户”）？描述声称的行为与实际实现是否一致？
3. **数据外传路径**——有没有把本地数据、凭据、对话内容发往外部的调用（网络请求、日志上报、遥测、错误上报）？每个出站目的地是否已向用户声明？
4. **权限最小化**——声明或请求的权限（文件写入、命令执行、网络、跨目录访问）是否超出功能所需？允许的工具范围或权限配置是否过宽？
5. **危险默认值**——是否默认自动执行写操作或破坏性命令而无需确认？失败时是否静默降级到更不安全的行为？
6. **供应链**——附带脚本是否已逐行阅读？实际行为与名称是否一致？依赖是否锁定、来源是否可信？安装 / 更新过程是否执行远程代码（如管道执行下载脚本、动态安装未固定版本的依赖）？
7. **凭据与敏感信息**——有无硬编码的密钥、令牌、内部地址？示例配置里是否含真实凭据？日志会不会打印敏感值？
8. **路径与边界逃逸**——路径拼接是否可能穿越目录（如 `../`）？操作是否被限制在声明的工作目录内？符号链接如何处理？
9. **诱导性描述**——description 是否夸大触发范围以劫持无关请求（“任何任务都应使用本技能”）？触发词与实际能力是否相符？
10. **残留与清理**——运行后留下什么（临时文件、后台进程、被修改的配置、注册的定时任务）？卸载是否干净？

外部基线（判断时对照；宿主具备联网检索能力时，主动核对下列基线的最新版本与新披露的攻击模式，不要仅凭记忆）：OWASP 面向 Agent 技能的十大风险清单；MCP 工具投毒相关研究；对市场技能漏洞模式的公开分类研究。
